# StarScope

中文 GitHub 项目变现潜力、商业价值测算、Star 排行、增长监控和收入披露站点。1.3.0 增加榜单后台更新与页面自动同步。商业价值页展示可调参数的保守、基准、积极三档月收入场景；有来源的真实披露保持独立。首页继续使用真实 GitHub 指标计算透明规则分。支持搜索、语言与主题筛选、新晋榜、监控快照、趋势详情和 CSV 导出。

## 启动

需要 Node.js 22 或更新版本；无需安装第三方依赖。

```sh
git clone https://github.com/henryli777/github-star-monitor.git
cd github-star-monitor
npm start
```

打开 [http://127.0.0.1:4320](http://127.0.0.1:4320)。服务只监听本机回环地址。端口已占用时，运行 `PORT=4322 npm start`。运行 `npm test` 执行自动化验证。

默认可以通过未认证公开 GitHub API 获取数据。若遇到额度限制，可在启动前设置服务端环境变量 `GITHUB_TOKEN`。Token 不会发送到浏览器或写入数据文件；服务不会自动加载 `.env`，环境变量修改后需重启。

## 排行口径

- 变现潜力：在当前 GitHub 搜索返回的前 50 个项目中，按关注度、Fork、维护时效和类别规则评分。它不是盈利概率或估值，尚未通过真实收入样本校准。
- 模拟月收入：Star × 假设月活比例 × 假设付费比例 × 假设月客单价。默认 10%、2%、CNY 50；10,000 Star 对应假设测算 CNY 1,000/月。参数保存在访客浏览器，币种仅代表假设计价，不做汇率转换。统一参数下，金额排序等价于 Star 排序；真实收入披露独立展示。
- 商业价值：默认场景采用保守（活跃 1%、付费 0.5%、CNY 20）、基准（5%、1%、CNY 50）、积极（10%、2%、CNY 100）三套示例假设；10,000 Star 对应 CNY 10、250、2,000/月。三档系数须非递减，非法输入保留上次有效结果。金额不是已校准预测区间，实际收入可能为零，未扣除成本，不代表利润或公司估值。Fork、维护与类别不直接乘入金额；研究规则分与金额独立排序。指标完整度只描述 Star、Fork、维护三项已知数据比例，不表示预测可信度。
- Star 总榜：GitHub 搜索返回的前 50 个公开、非 Fork、未归档仓库，按当前 Star 排序。筛选后，排名属于对应查询结果，不代表完整 GitHub 数据库。
- 新晋热门：最近 30 天创建的仓库，按当前 Star 排序，不表示 30 天净增长。
- 日、周、月增长：仅覆盖已监控项目，分别比较 24 小时、7 天、30 天附近的真实快照。基线须不晚于目标时间且偏差不超过 2 小时；历史不足显示“—”，净增长可以为负。
- 真实披露：商业价值页的独立标签，只比较同币种、同周期的最新披露，不累计历史披露、不换算币种。场景金额从不写入或混入披露排行；没有披露不表示零收入。每条记录需金额、币种、周期、非未来披露日期与 HTTP(S) 来源。日期按 Asia/Shanghai 判断。

GitHub 不提供项目收入。本站收入记录是来源方声明，未经财务审计。MRR、ARR、实际到账收入和利润必须区分，录入时请在备注中注明。没有预置虚构收入、模拟增长或虚构历史。数据说明页的 Ghost 公开参考只标注原文“$”，币种不明确，因此不加入 USD/CNY/EUR 收入榜。

搜索可能返回 `incomplete_results`；页面会说明。榜单缓存 15 分钟，上游失败时返回对应查询的旧缓存并保留原采集时间。无缓存时显示错误及重试入口。未认证常规接口通常限 60 次/小时，搜索另有限额；具体以 GitHub 当时规则为准。

## 数据更新

服务启动时检查总榜和新晋榜的缓存，此后每 15 分钟在后台更新这两个固定榜单，关闭浏览器也会继续。搜索及语言、主题筛选仍按对应查询共享 15 分钟缓存，不为每个访客重复强制采集。

可见页面每 60 秒同步共享数据，重新回到前台或恢复联网时也会同步；隐藏页面不轮询。监控视图切入时重新读取服务端快照。Star 更新后，当前参数下的月收入场景重新计算，不改参数、不刷新整页，也不将模拟金额写入真实披露。

同步失败保留已有数据和真实采集时间；遇到 GitHub 限流按其重置时间或重试提示等待，网络失败短暂退避。页面同步周期不是上游采集周期，不能保证 GitHub 的搜索索引实时更新。默认无 Token，20 个监控继续按每小时采集，避免仅监控就超过匿名接口通常的每小时 60 次额度。

## 监控与保存

最多监控 30 个项目。服务运行期间，每小时尝试采集；关闭浏览器不影响后台采集，停止 Node 服务则停止采集。手动刷新最多同时请求 3 个仓库，失败的项目保留已有数据、历史和实际采集时间，失败提示会持久保存。

真实快照保留最近 90 天。取消监控停止后续采集，已有历史保留在本地；再次添加可继续使用。仓库重命名或转移后更新规范仓库名并保留历史。刷新期间移除并重新添加项目，不会被旧请求覆盖。

榜单缓存、监控、历史与收入记录原子保存至 `data/state.json`。浏览器刷新和服务重启后保留，`data/` 不提交 Git。数据损坏时服务拒绝覆盖原文件。一个数据目录同时只应由一个服务进程使用。

榜单“导出”下载当前视图 CSV；顶栏下载图标导出监控、历史与收入 JSON。首版没有 JSON 导入界面；完整迁移或恢复请在停止服务后恢复备份的 `data/` 目录。工作空间 JSON 导出是可读数据导出，不是可直接覆盖 `state.json` 的同结构文件。没有账户、支付、广告管理或跨设备同步。

## 公网部署

部署目标为 `43.108.37.222`，域名为 `github.coinexo.top`。Docker Compose 只发布服务器回环端口 `4320`，由独立 Nginx 站点代理；使用公开只读模式，访客不能更改服务端监控或收入记录。首次部署采集 20 个真实项目作为监控基线，增长榜需要等待后续历史积累。

部分初始采集失败会每小时重试。重启时若监控不足配置数量，会从当时榜单补足剩余位置，保留已有项目和历史。公开详情采用 15 分钟缓存、并发去重与每小时最多 20 次共享新增请求预算；缓存详情和后台监控采集不消耗该预算。

运行 `npm run build` 生成 `output/release/`，包含带内容版本的静态资源，不包含凭据、监控数据或测试数据。完整步骤、HTTPS 与回滚命令见 [部署说明](docs/deployment.md)。评分和金额假设见 [变现潜力口径](docs/commercial-potential.md)。

## 文件

| 文件 | 用途 |
| --- | --- |
| `public/` | 中文响应式界面与浏览器数据逻辑 |
| `public/potential.mjs` | 可解释规则分与模拟收入纯函数 |
| `public/economics.mjs` | 三档月收入场景、独立排序与指标完整度 |
| `public/refresh-controller.mjs` | 可见页面同步、重新联网与单次请求协调 |
| `server.mjs` | HTTP 服务、API、Origin/Host 限制与定时刷新 |
| `lib/github.mjs` | 官方 GitHub 请求、缓存、搜索与仓库校验 |
| `lib/store.mjs` | 持久化、快照、收入与刷新身份保护 |
| `test/` | Node 内置行为与回归测试 |
| `docs/design.md` | 范围、数据口径和 API 契约 |
| `docs/verification.md` | 本次验证结果与实际限制 |

API 只读取公开仓库，Token 配置不改变公开范围。静态服务仅允许 `public/`，拒绝路径穿越与符号链接；跨网站写入被拦截。公网模式使用共享缓存、受限流保护的只读接口和独立容器运行环境，不提供个人私有工作空间；本地模式继续支持监控与收入管理。
